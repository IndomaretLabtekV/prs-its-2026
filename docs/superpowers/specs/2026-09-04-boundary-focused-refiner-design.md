# H16 Boundary-Focused Refiner Design

## Status

APPROVED DESIGN - 2026-09-04

## Goal

Test whether training the existing V9 boundary refiner with higher weight on
rows near the 5% audit boundary improves honest pooled OOF ranking. The goal is
to maximize feature-only OOF performance; `98.55` is a stretch target, not a
guaranteed acceptance criterion.

## Non-goals and constraints

- Do not use test labels, reconstructed labels, public leaderboard feedback, or
  external data.
- Do not use `claim_id`, source row position, or any storage-order proxy as a
  feature or selector.
- Do not change the frozen V8 stack, fold assignments, V9 feature set, or
  inference rank-combination rule.
- Do not run an unbounded hyperparameter sweep.

## Hypothesis

H10 showed that V9 features help the boundary refiner by +2 TP, while H15
showed that global positive-class weighting hurts by 9-12 TP. The remaining
testable hypothesis is that the refiner should spend more training capacity on
the rows whose ordering can change the top-5% portfolio, rather than weighting
all fraud rows equally.

Prediction: a boundary-focused sample-weight arm will improve pooled OOF
NR@5% and TP over the unweighted H10 V9 control without materially reducing AP.
The expected gain is modest; failure closes this refiner-objective branch.

## Fixed data and model

- Data: `data/train.csv`, using target column `label`.
- Fold assignments: authoritative `results/v8/results.zip` assignments.
- Base stack: frozen V8 OOF stack and fold-local percentile rank.
- Candidate pool: frozen top 10% of `STACK_RANK_OOF`.
- Refiner features: frozen H10 `V9_FEATURES` on `train_v9`.
- Refiner: CatBoost Logloss, depth 7, 900 iterations, learning rate 0.035,
  and all other H10 parameters unchanged.
- Seeds: `CFG.seed + 3000 + fold`.
- Control: saved unweighted H10 V9 OOF scores.

## Boundary weighting

For each training row in the candidate pool, use its fold-local stack rank
`r = STACK_RANK_OOF[i]`. The audit boundary is `b = 0.95`, and the focus band
is `d = 0.02`. The sample weight is:

```
weight(i, alpha) = 1 + alpha * max(0, 1 - abs(r - b) / d)
```

This weight is label-independent and only changes the CatBoost training loss.
Rows exactly at the boundary receive `1 + alpha`; rows at least 0.02 away
receive weight 1. The model still predicts using V9 features only, and the
existing boundary rank-combination remains unchanged.

The confirmatory arms are `alpha = 1`, `3`, and `7`. These give maximum row
weights of 2, 4, and 8, respectively, and are run once with fixed fold seeds.

## Evaluation

For every arm, build OOF predictions by fitting only on the candidate rows of
the four training folds and predicting the held-out candidate rows. Combine
the refiner rank with the frozen stack rank exactly as H10, then compute:

- pooled `NR@5%` and fraud captured;
- Average Precision;
- per-fold TP and TP delta versus the H10 V9 control;
- finite-score, pool-coverage, and two-class training sanity checks.

The promotion gate remains the pre-registered gate: at least +8 pooled TP,
`NR@5%` delta at least +0.001, at least three fold wins, worst fold delta no
worse than -2 TP, and AP delta at least -0.001. An arm below the gate is a
negative result, even if it is the best of the three.

## Failure handling and decision

If the baseline cannot be reproduced, stop before interpreting challenger
metrics. If a fold has a single-class candidate pool, stop and report the
protocol incompatibility instead of changing the split. If all arms fail the
promotion gate, record H16 as refuted and do not widen the alpha or band sweep.
